# Buffalo data and model plan

## Local archive intake — Aarjav

The roughly 10 GB ZIP is on Aarjav’s PC. The Drive folder is useful as a source reference or for selected files if access permits. Neither archive contents nor GPS coverage have been verified. The teammate’s handoff manifest lists 947 pre-exported frames. Reuse the approved, verified subset and sample new footage only for gaps in diversity, GPS coverage, or labeling requirements. See [handoff-integration.md](handoff-integration.md). Start implementation with a small representative set of extracted clips plus their companion files. Run the full intake where the archive already lives, with room for the uncompressed archive, intermediates and approved derivatives. Estimate disk and derivative growth from a pilot. Keep raw footage, GPS logs and large model artifacts out of Git. Review authorization before sharing any footage or location metadata.

1. **Inventory.** Plan `inspect_archive.py` for a local directory. Probe container, codec, duration, dimensions, nominal and effective frame rate, rotation, PTS and metadata with ffprobe. Inspect timed GPS with ExifTool or a supported camera-specific parser when standard tags are absent. Detect matching GPX, NMEA and CSV companions and report ambiguity, timestamp range/timezone confidence, point count, GPS coverage and gaps. Write a versioned JSON manifest with relative paths, checksums or stable IDs, source precedence, and per-file errors. Identify unsupported, corrupt, duplicated and video-only inputs. Several clips may belong to one physical drive.
2. **Align and register.** Plan `ingest_drive.py` to use the manifest and explicit drive grouping and UTC capture anchors. Inspect PTS drift and align GPS with an agreed clock offset (DDL stores video clock minus GPS clock) and drift correction if warranted. Check overlap and at least one route/time anchor before accepting alignment. Register idempotent drive and GPS point IDs, preserve raw and snapped geometries and OSM way IDs, and keep unmatched points visible in quality summaries. Store pseudonymous drive/vehicle IDs.
3. **Privacy and frames.** Use OpenCV with validated face and license-plate detectors to redact exports before samples reach shared storage, Kafka or labeling. If issuing a blurred video derivative, redact every frame. Audit challenging day/night/weather samples, record blur provenance and quarantine or manually review failures. Sample by PTS at configurable FPS, normalize rotation, and publish rows only when approved derivative files exist. Use staged files and a resumable ingest ledger. Interpolate car position and speed between valid GPS points within a bounded gap and handle heading wraparound. Allow null GPS when interpolation is unsupported. Report the percentage of frames eligible for mapping.
4. **Weather join.** Match the frame capture UTC hour to the most appropriate valid KBUF observation in that hour within a documented tolerance and persist its actual `observed_at` as `frames.weather_hour`. The attached snapshot starts at 00:54 UTC on 2019-01-01 and ends at 23:54 UTC on 2026-10-20, so joining on equality to a truncated timestamp would miss records. Preserve an explicit unknown bucket. Treat station conditions as area metadata and derive day/night from capture time and position or manual review.
5. **Labeling sample.** Plan `sample_for_labeling.py` for a reproducible, seeded sample of ~1,000 approved frames. Stratify by drive, corridor, local time of day and weather. Oversample snow, rain, night and high-311-pothole corridors such as Main Street when present. Use time/distance spacing and near-duplicate checks, and keep clean images and difficult negatives. Treat 311 as a sampling signal. Export images, YOLO label directories, class names, dataset metadata and manifest for CVAT or an explicit Label Studio YOLO import/export conversion. Track unlabeled and reviewed-clean images separately and verify a box and an explicit negative on a round trip.

## Labels, training and serving — Rishi

1. **Freeze group membership.** Group clips by physical drive, including overlapping exports of the same footage, and check near-duplicates before partitioning. Start from a proposed 70/15/15 drive-group train/val/test split and adjust against available route, class and weather coverage. Record one versioned assignment per drive and enforce it in `frames.split`, dataset materialization and verification queries. Freeze the Buffalo test set before tuning. If enough drives exist, report a corridor-held-out sensitivity check.
2. **Define and review annotations.** Document box policy, class order, minimum visible evidence, overlapping damage, occlusion and reviewed negatives. Clarify treatment of roadkill, stalled cars and ambiguous debris before labeling. Use YOLO-World prompts for road obstacles (e.g. fallen branch or tire), animals/roadkill and crash scenes. Map prompt outputs into canonical classes, use suppression and confidence to prioritize review, and include provenance for generated candidates. Human reviewers accept, edit or reject every candidate used as a target. Use manually reviewed labels for validation and test. Log class counts, annotator disagreements and gaps.
3. **Baseline and fine-tune.** Run the existing four-class YOLOv8s/RDD2022 weights on the frozen Buffalo evaluation workflow, then fine-tune YOLOv8s on eligible seven-class training data. Document weights hash, dataset hash, split manifest, seed, dependencies, configuration and hardware. Include only licensed, reviewed rare-hazard supplements and keep them in training. Choose hyperparameters and thresholds on validation. Evaluate the selected model once on the frozen test set and report mAP50, mAP50–95, per-class precision/recall and support. Break down dry, rain, snow/ice, other and unknown weather and report night independently. Mark sparse/unavailable strata and do not assign baseline AP to classes it cannot predict.
4. **Export and benchmark.** Plan `export_onnx.py` to package ONNX plus class order, input dimensions, preprocessing/letterbox, normalization, output decoding and NMS ownership, confidence policy, opset, provenance and digest. Check PyTorch/ONNX detections on reference frames with defined tolerances for classes, confidence and box overlap. Benchmark after warmup at the intended batch size on CPU and available accelerated providers. Report image decode/preprocess, inference, postprocess and end-to-end worker time, FPS, p50/p95 latency, provider versions and hardware. Keep throughput evidence separate from replay schedule.
5. **Kafka worker.** Plan `detector_worker.py` to load the approved model bundle, resolve approved image refs within configured storage, resize/normalize identically to evaluation, infer and map surviving boxes back to source dimensions. Publish schema-valid results for clean and positive frames along with failure outcomes and telemetry. Validate model version and class order at startup. Commit input offsets after publication acknowledgement and exercise redelivery. Give Aarjav a small known-good frame and batch fixture plus deployment and benchmark instructions.

## Shared acceptance exercises

- Replay a privacy-approved pilot at 1× and then faster. Verify frame counts and capture ordering, worker output completeness, PostGIS pin updates and visible Grafana panels for map, lifecycle, inference health and draft queue. Use approved thumbnails/overlays if enabled.
- Replay annotated same-location and nearby-distinct cases, a pass with complete clean coverage, a pass with gaps, late results and worker interruption. Quantify positional error and false merge/split behavior with independent labels or surveyed locations.
- Record which rare classes and weather slices have enough held-out observations, and show the model quality and latency results with actual support and runtime hardware.
